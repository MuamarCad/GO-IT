## 1. Контекст проекта

### 1.1 Назначение

GO-IT — студенческий MVP образовательной платформы для знакомства с IT-профессиями. Подробнее: [SPECIFICATION.md](SPECIFICATION.md#1-назначение).

**Ключевое ограничение:** демонстрационный проект для защиты, без цели публичного деплоя.

### 1.2 Текущий статус

| Аспект | Состояние |
|--------|-----------|
| Реализация | 95% функциональности из MVP-плана |
| Документация | README, SPECIFICATION.md (v1.2), GIGACODE.md (v1.2) |
| Деплой | Локальный через Docker Compose |
| Архитектура | Layered (близкая к Hexagonal) |
| Стек | Go 1.22, chi, pgx, html/template, HTMX |
| Авторизация | ✅ OAuth (GitHub, VK, Yandex) |
| Личные кабинеты | ✅ Student, Mentor, Partner |

## 2. Цели развития

### 2.1 Главная цель

Довести GO-IT до уровня, при котором проект:

1. **Проходит защиту без замечаний** — все проверки `README` успешны
2. **Демонстрируется стабильно** — без утечек памяти, падений, ошибок
3. **Код читаем и документирован** — новый участник понимает архитектуру за 30 минут
4. **Готов к продолжению** — в следующем семестре можно расширять, не переписывая

### 2.2 Измеримые цели

| № | Цель | Метрика | Приоритет |
|---|------|---------|-----------|
| C1 | Все тесты проходят локально и в CI | `go test ./...` зелёный на clean repo | 🔴 Критично |
| C2 | Нет утечек памяти при длительной работе | Нет роста RSS > 50 МБ за 24 часа | 🔴 Критично |
| C3 | Код документирован | `go doc ./internal/...` показывает описания | 🟡 Важно |
| C4 | Покрытие тестов ≥ 60% | `go test -cover ./...` | 🟡 Важно |
| C5 | Сценарий защиты работает от нуля до демо за 5 минут | Репетиция без ошибок | 🔴 Критично |

## 4. План развития

### Фаза 1: Критические исправления (1-2 дня)

**Цель:** Устранить блокирующие проблемы, которые могут сломать демо.

#### Задача 1.1: Удалить пустые директории

- **Зависит от:** none
- **Deliverable:** Директории `internal/app/`, `internal/http/middleware/`, `migrations/`, `tests/` удалены
- **Done when:**
  - `ls internal/app/` выдаёт error
  - `git status` чистый (без удалённых файлов, только удаление директорий)

#### Задача 1.2: Добавить cleanup сессий в session.Manager

- **Зависит от:** none
- **Deliverable:** Сессии старше 24 часов автоматически удаляются
- **Done when:**
  - В `Manager` добавлена goroutine с ticker (every 1h)
  - Тикер очищает `store` от записей с `MaxAge` истёкшим
  - `go test -race ./internal/session/` проходит
  - RSS не растёт при `stress test` (1000 запросов)

#### Задача 1.3: Задокументировать domain модели

- **Зависит от:** none
- **Deliverable:** Все публичные типы в `domain/models.go` имеют doc-comments
- **Done when:**
  - `go doc go-it/internal/domain` показывает описания для Direction, CareerCase, Mentor, Application и т.д.
  - Каждый struct имеет comment, поясняющий назначение

#### Задача 1.4: Добавить middleware логирования

- **Зависит от:** 1.1 (пустые директории удалены)
- **Deliverable:** Логирование метода, пути, статуса, duration
- **Done when:**
  - Создан `internal/http/middleware/logging.go`
  - Middleware подключён в `router.go`
  - Логи появляются в `docker compose logs`
  - Формат: `[2026-11-10 12:00:00] GET /cases/frontend 200 45ms`

**Критерии завершения Фазы 1:**
- [ ] `git status` чистый
- [ ] `go test ./...` проходит
- [ ] `go test -race ./...` проходит
- [ ] `docker compose up --build` поднимает сайт

### Фаза 2: Стабильность и тесты (2-3 дня)

**Цель:** Повысить надёжность и покрытие тестов до приемлемого уровня.

#### Задача 2.1: Тесты session.Manager

- **Зависит от:** 1.2 (cleanup добавлен)
- **Deliverable:** `session/session_test.go` с покрытием
- **Done when:**
  - Тесты: генерация ID, CSRF-валидация (валидный/невалидный/отсутствует)
  - Тест: cleanup удаляет старые сессии
  - Тест: race-condition под `go test -race`
  - Покрытие пакета ≥ 80%

#### Задача 2.2: Настроить GitHub Actions

- **Зависит от:** none
- **Deliverable:** CI-пайплайн на каждом push
- **Done when:**
  - `.github/workflows/ci.yml` существует
  - Запускает: `go fmt`, `go vet`, `go test ./...`
  - Status badge виден в README
  - Failing build блокирует merge (через branch protection)

#### Задача 2.3: Интеграционные тесты для postgres

- **Зависит от:** 2.2 (CI настроен)
- **Deliverable:** Тесты postgres-репозитория
- **Done when:**
  - `internal/repository/postgres/postgres_test.go` существует
  - Тесты: `Connect`, `Create`, `GetMentor`, `ListMentors`
  - Использует `testcontainers-go` или docker compose `test`-сервис
  - Проходит в CI

#### Задача 2.4: Закрыть пробелы покрытия

- **Зависит от:** 2.2
- **Deliverable:** Покрытие ≥ 60%
- **Done when:**
  - `go test -cover ./...` показывает ≥ 60%
  - Закрыты пробелы: `config`, `render`, `cases`
  - `config/config_test.go` — тесты Load() (валидация)
  - `http/render/render_test.go` — тесты рендеринга (base + pages)

**Критерии завершения Фазы 2:**
- [ ] Coverage ≥ 60%
- [ ] CI passing на clean repo
- [ ] Integration tests passing
- [ ] `go doc ./internal/...` показывает все doc-comments

### Фаза 3: Качество кода (3-4 дня)

**Цель:** Улучшить структуру кода, сделать его поддерживаемым.

#### Задача 3.1: Разделить handlers по доменам

- **Зависит от:** 2.4 (тесты стабильны)
- **Deliverable:** Handlers разделены по файлам
- **Done when:**
  - Созданы: `cases_handler.go`, `mentors_handler.go`, `volunteering_handler.go`, `content_handler.go`, `health_handler.go`
  - Методы перемещены из `handlers.go` в соответствующие файлы
  - Все тесты проходят
  - Diff читаемый, no logic changes

#### Задача 3.2: Вынести middleware в отдельный пакет

- **Зависит от:** 3.1 (структура стабилизировалась)
- **Deliverable:** `LimitBody` и `RequestID` в `middleware/`
- **Done when:**
  - `internal/http/middleware/body_limit.go`
  - `internal/http/middleware/request_id.go`
  - Вызовы в `router.go` обновлены

#### Задача 3.3: Интегрировать catalog в интерфейс

- **Зависит от:** 3.1 (handlers разделены)
- **Deliverable:** `Directions()` вызывается через `Catalog`
- **Done when:**
  - `Catalog` имеет метод `Directions(ctx)`
  - `memory.Store` и `postgres.Store` реализуют
  - `caseForRoadmap` переписан на `Catalog.Directions()`
  - Направления можно подменить в тестах

#### Задача 3.4: Добавить doc-comments к экспортируемым функциям

- **Зависит от:** none
- **Deliverable:** Все public методы имеют doc-comments
- **Done when:**
  - `go doc ./internal/service/` показывает описания
  - `go doc ./internal/repository/` показывает описания
  - `golangci-lint` (если подключён) не ругается

**Критерии завершения Фазы 3:**
- [ ] `gofmt -l .` не показывает файлов
- [ ] `go doc` показывает описания
- [ ] Handlers разделены
- [ ] Middleware в правильном месте

## Приложение A: Чек-лист готовности к защите

### А.1 Базовые проверки

- [ ] `docker compose down -v && docker compose up --build` поднимает сайт и БД
- [ ] `go test ./...` проходит без ошибок
- [ ] `go test -race ./...` проходит без race conditions
- [ ] Сайт доступен по `http://localhost:8080`
- [ ] `/health/live` возвращает `ok` с кодом 200
- [ ] `/health/ready` возвращает `ok` когда БД доступна
- [ ] Кейс проходит от начала до результата за ≤ 4 шага
- [ ] Заявка ментору сохраняется в PostgreSQL
- [ ] После перезапуска контейнеров заявка остаётся
- [ ] Переключение темы работает
- [ ] В `.gitignore` есть `.env`
- [ ] В Git нет `.env` или других секретов

### А.2 Проверки безопасности

- [ ] Отправка POST без CSRF-токена → 403
- [ ] Отправка POST с невалидным CSRF → 403
- [ ] Markdown-контент санитизирован (bluemonday)
- [ ] SQL-инъекция через форму заявки → параметризованный запрос
- [ ] Тело запроса > 1 МБ → отклоняется
- [ ] Страница ошибки не раскрывает stack trace
- [ ] Non-root пользователь в Docker
- [ ] Секреты через ENV-переменные

### А.3 Проверки документации

- [ ] README актуален, содержит сценарий демонстрации
- [ ] ARCHITECTURE.md содержит схему слоёв и объяснение DI
- [ ] SPECIFICATION.md обновлён, все статусы отражают реальность
- [ ] `go doc ./internal/...` показывает doc-comments
- [ ] GIGACODE.md актуален (можно использовать для AI-контекста)

### А.4 Репетиция защиты

- [ ] Сценарий отработан минимум 2 раза
- [ ] Время демонстрации ≤ 7 минут
- [ ] Запасной план: `make run` если docker падает
- [ ] Скриншоты или ASCII-схеты готовы для README
- [ ] Все команды `make` протестированы

### А.5 Проверки авторизации и ЛК

- [ ] `/auth` открывается без ошибок
- [ ] OAuth-провайдеры (GitHub, VK, Yandex) редиректят на страницу входа провайдера
- [ ] Callback после OAuth создаёт сессию и редиректит на нужный LK
- [ ] `/lk/student` открывается для ученика
