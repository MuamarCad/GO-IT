# IT Project Manager

Маршрут знакомства с ролью: не «управлять людьми», а прояснять результат, когда требования неполные.

## Цель направления

Научиться формулировать задачу так, чтобы разработчик мог её проверить: цель, ограничение, критерий готовности. После маршрута вы отличите демо-MVP от «давайте сразу платформу с чатом и ботом».

## Базовые знания

- Разница между проблемой пользователя и списком фич.
- Зачем нужны границы MVP (Must / Should / не входит).
- Как выглядит пользовательский сценарий в 4–7 шагов.
- Что считать критерием приёмки.

## Порядок тем

1. Аудитория: школьник, студент, наставник, организация.
2. Сценарий «первый кейс»: выбор → вопрос → проверка сервером → результат.
3. Приоритизация: если сроки горят, режем контент, а не качество главного сценария.
4. Коммуникация с командой: общий словарь маршрутов и сущностей.
5. Демо: 5–7 минут, один сквозной путь, честно названные заглушки.

## Практические мини-проекты

- Описание одной волонтёрской задачи: навыки, масштаб, ожидаемый результат.
- Сценарий защиты GO-IT по минутам.
- Критерии готовности чеклистом, а не «сделать красиво».

## Критерии прогресса

- Вы можете сказать, чего в MVP нет, не извиняясь.
- У каждой формы есть понятный следующий шаг.
- Результат кейса сопровождается дисклеймером.
