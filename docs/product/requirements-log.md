# Журнал требований заказчика

**Статус:** Действует
**Владелец:** Системный аналитик
**Обновлено:** 2026-11-13

Журнал фиксирует замечания и требования заказчика и их фактическое состояние. Исходные тексты лежат в `client-requirements/` (папка в `.gitignore`, формат — [шаблон](../templates/requirement.md)), в Git попадает только этот журнал. Функциональные требования, в которые превращаются замечания, описаны в [спецификации](specification.md).

## Как вести журнал

1. Новое замечание получает номер `REQ-NNN` (сквозной), исходный текст сохраняется в `client-requirements/` по шаблону.
2. Аналитик разбирает замечание на пункты и добавляет строки в таблицу ниже со статусом `Новое`.
3. Статусы: `Новое`, `В работе`, `Выполнено`, `Отклонено` (с причиной). Статус «Выполнено» ставится по [правилу подтверждения](../standards/documentation-standard.md#8-правило-подтверждения-статусов): с тестом, который воспроизводит именно замечание заказчика.
4. Решения, которые меняют требования (заказчика или владельца проекта), записываются в раздел «Решения» с датой и автором.
