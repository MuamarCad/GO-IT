# ADR-0003: Контент как код в репозитории

**Статус:** Принят
**Владелец:** Tech Lead
**Обновлено:** 2026-11-13
**Дата решения:** 2026-11-05

## Контекст

Roadmap, статьи, кейсы и каталоги пишут и правят студенты. CMS, админки и отдельной базы контента нет, а изменения контента должны проходить ревью так же, как код.

## Решение

Roadmap и статьи — Markdown, схемы roadmap — JSON в `content/`. Кейсы и начальные каталоги — Go-код (`internal/cases`, `internal/catalog`). Markdown санитизируется (bluemonday), схема и данные кейсов проверяются тестами при каждом запуске.

## Рассмотренные альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---------|-------|--------|------------------|
| База данных и админка | Редактирование без деплоя | Нужна авторизация, миграции, интерфейс | Вне границ MVP |
| Внешняя CMS | Готовый интерфейс | Новая зависимость и доступы | Лишняя инфраструктура |

## Последствия

Плюсы: версионирование и ревью контента, воспроизводимость, автоматическая валидация. Минусы: изменить контент можно только пересборкой и деплоем; Markdown читается при каждом запросе (кеша нет). Правила формата — в [руководстве по контенту](../../engineering/content-guide.md).
