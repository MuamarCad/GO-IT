## 1. Назначение

Спецификация описывает поведение, архитектуру и требования платформы GO-IT — адаптивной веб-платформы для знакомства с IT-профессиями через интерактивные кейсы, дорожные карты и механизмы взаимопомощи (менторство, волонтёрство).

Спецификация служит основой для:
- обратной связи по функциональности;
- планирования дальнейшей разработки;
- оценки соответствия реализации требованиям;
- онбординга новых участников команды.

## 2. Область применения

### 2.1 Целевые аудитории

| Роль | Потребность | Используемые функции |
|------|-------------|---------------------|
| Школьник | Понять, какие IT-профессии существуют | Кейсы, описания направлений, roadmaps |
| Студент младших курсов | Выбрать специализацию | Материалы, практические сценарии |
| Студент-наставник | Помочь начинающим | Профиль, обработка заявок |
| Студент-волонтёр | Применить навыки для социальной задачи | Каталог задач, форма отклика |
| Социальный партнёр | Размещать волонтёрские задачи | ЛК партнёра, аналитика, управление заявками |

### 2.2 Используемые сценарии

- **«Первый кейс»** — пользователь выбирает направление, отвечает на вопросы, получает результат с пояснениями и ссылками на roadmap.
- **P2P-менторство** — пользователь изучает профиль ментора, отправляет заявку на консультацию.
- **Цифровое волонтёрство** — пользователь изучает задачу от социальной организации, отправляет отклик.
- **Дорожные карты** — пользователь изучает структурированный план обучения по направлению.
- **Блог** — пользователь читает вводные статьи о выборе пути в IT.

## 3. Пользовательские пользовательские сценарии

### 3.1 Сценарий «Пройти кейс Frontend»

```
Пользователь          GO-IT
    │                    │
    │──── GET /directions ────► Каталог направлений
    │◀─── Карточки (Frontend, Backend, PM)
    │
    │──── GET /directions/frontend ────► Страница направления
    │◀─── Информация + кнопка «Пройти кейс»
    │
    │──── GET /cases/frontend ──────► Вопрос 1
    │◀─── Формулировка + 3 варианта
    │
    │──── POST /cases/frontend/answer ────► Вариант B
    │                    │ (сервер валидирует, сохраняет)
    │◀─── 302 → /cases/frontend (вопрос 2)
    │
    │──── GET /cases/frontend ──────► Вопрос 2
    │
    │──── POST /cases/frontend/answer ────► Вариант A
    │◀─── 302 → /cases/frontend (вопрос 3)
    │
    │─── ... вопрос 4 ────►
    │
    │◀─── 302 → /cases/frontend/result
    │
    │──── GET /cases/frontend/result ────► Результат
    │◀─── 4/4 баллов, пояснения, ссылка на roadmap
```

**Требования:**
- Состояние сохраняются в серверной сессии.
- Результат (балл) рассчитывается **только** на сервере.
- Невалидный вариант ответа отклоняется с сообщением об ошибке.
- Пропуск обязательных шагов невозможен.
- Повторная отправка не начисляет баллы дважды.

### 3.2 Сценарий «Оставить заявку ментору»

```
Пользователь          GO-IT
    │──── GET /mentors ────► Каталог менторов
    │◀─── Карточки с фильтрацией
    │
    │──── GET /mentors/backend-developer ────► Профиль ментора
    │◀─── Имя, специализация, темы, форма
    │
    │──── POST /mentors/backend-developer/applications ────► Форма (name=Анна, contact=anna@mail.ru, message=Помогите с PostgreSQL)
    │                    │ (валидация, проверка существования ментора)
    │◀─── 302 → /mentors/backend-developer?sent=1
    │
    │──── GET /mentors/backend-developer?sent=1 ────► Подтверждение
    │◀─── «Заявка отправлена»
```

**Требования:**
- Валидация: имя 2-100 символов, контакт 3-254 символа, сообщение ≤ 2000 символов.
- `target_id` проверяется на существование перед сохранением.
- Невалидные поля возвращаются с ошибками (422).
- Запись сохраняется в БД со статусом `new`.

### 3.3 Сценарий «Изучить roadmap»

```
Пользователь          GO-IT
    │──── GET /roadmaps ────► Список roadmaps
    │◀─── Frontend, Backend, Project Manager
    │
    │──── GET /roadmaps/frontend ────► Страница roadmap
    │◀─── Описание, визуальная диаграмма (9 этапов), панель тем
    │
    │──── Клика по узлу диаграммы ────► Боковая панель с summary + ссылками
    │◀─── До 400 символов описания + до 5 внешних https-ссылок
    │
    │──── Якорь /roadmaps/frontend#t-forms-accessibility ────► Прокрутка к теме
    │◀─── Панель тем прокручена к нужной
```

**Требования:**
- Диаграмма рендерится из `content/roadmaps/{slug}.diagram.json`.
- Каждый узел имеет уникальный `id` (латиница + дефисы).
- Узлы с `href` (внутренний путь) ведут на страницы сайта.
- Узлы с `links` (внешние https) — открываются в боковой панели.

### 3.6 Сценарий «OAuth-авторизация»

```
Пользователь          GO-IT
    │──── GET /auth/github ────► Редирект на GitHub OAuth
    │◀─── 302 → https://github.com/oauth/authorize
    │
    │──── Callback после авторизации ────►
    │──── POST /auth ────► Обмена кодом на токен
    │                    │ (создание/поиск User, создание LoginSession)
    │◀─── 302 → /lk/student
    │
    │──── GET /lk/student ────► Личный кабинет ученика
    │◀─── Профиль, прогресс по кейсам, сохранённые roadmaps
```

**Требования:**
- Поддержка провайдеров: GitHub, VK, Yandex ID.
- При первом входе — автоматическое создание User.
- Роли назначаются пользователем после входа.
- Сессия хранит UserID, Role, ExpiresAt, CSRF.

### 5.2 Схема PostgreSQL

```sql
mentors (
  slug TEXT PRIMARY KEY,
  display_name TEXT, specialization TEXT, level TEXT,
  format TEXT, topics TEXT, description TEXT
)

volunteer_requests (
  slug TEXT PRIMARY KEY,
  title TEXT, organization TEXT, category TEXT,
  skills TEXT, scale TEXT, description TEXT, expected_result TEXT
)

applications (
  id BIGSERIAL PRIMARY KEY,
  kind TEXT CHECK (kind IN ('mentor', 'volunteer')),
  target_id TEXT NOT NULL,
  name TEXT NOT NULL,
  contact TEXT NOT NULL,
  message TEXT,
  status TEXT CHECK (status IN ('new', 'reviewed', 'closed')) DEFAULT 'new',
  role TEXT CHECK (role IN ('student', 'mentor', 'partner')),
  created_at TIMESTAMPTZ DEFAULT now()
)

sessions (
  id TEXT PRIMARY KEY,
  user_id TEXT,
  data JSONB NOT NULL,
  expires_at TIMESTAMPTZ NOT NULL
)

schema_migrations (
  version TEXT PRIMARY KEY
)
```

### 9.2 Формат roadmap-диаграммы

```json
{
  "stages": [
    {
      "id": "basics",
      "title": "Основы",
      "choose": false,
      "nodes": [
        {
          "id": "html-basics",
          "type": "core",
          "summary": "HTML-разметка форм",
          "links": [
            { "href": "/roadmaps/frontend#html", "title": "Справочник" }
          ]
        }
      ]
    }
  ]
}
```

**Правила валидации диаграммы:**
- `id` — уникален в рамках диаграммы (латиница + дефисы).
- `type` — один из `core`, `also`, `optional`.
- `choose` — `true` на одном этапе (выбор одного).
- `summary` — максимум 400 символов.
- `links` — максимум 5 ссылок, только `https://`.
- Каждый узел имеет ровно один из `href` (внутренний путь) ИЛИ `summary`+`links` (внешние ссылки).

### 9.3 OAuth-провайдеры

Поддерживаемые провайдеры для авторизации: GitHub, VK, Yandex ID. При первом входе через провайдера создаётся User с ролью, выбранной пользователем.

### 9.4 User flows (авторизация и ЛК)

**Flow 1: OAuth-вход**

```
Пользователь          GO-IT
    │──── GET /auth/github ────► Редирект на GitHub OAuth
    │◀─── 302 → https://github.com/oauth/authorize
    │
    │──── Callback ────►
    │──── POST /auth ────► Обмен кодом на токен
    │                    │ (создание User, создание сессии)
    │◀─── 302 → /lk/student
    │
    │──── GET /lk/student ────► Личный кабинет
    │◀─── Профиль, прогресс, roadmaps
```

**Flow 2: Выход из ЛК**

```
Пользователь          GO-IT
    │──── POST /lk/*/logout ────►
    │                    │ (сброс сессии)
    │◀─── 302 → /
```

**Flow 3: Доступ к ЛК без авторизации**

```
Пользователь          GO-IT
    │──── GET /lk/student (без сессии) ────►
    │                    │ (middleware: check session)
    │◀─── 302 → /auth
```

## 10. Конфигурация

| Переменная | По умолчанию | Описание | Обязательность |
|-----------|-------------|----------|---------------|
| `APP_ENV` | `development` | Окружение | No |
| `HTTP_ADDR` | `:8080` | Адрес сервера | No |
| `DATABASE_URL` | (пусто) | PostgreSQL URL | No (обязательно в production) |
| `SESSION_SECRET` | `dev-session-secret-...` | Секрет для HMAC сессий | No (min 16 chars в prod) |
| `CSRF_SECRET` | `dev-csrf-secret-...` | Секрет для CSRF-токенов | No (min 16 chars в prod) |

**Валидации:**
- В `production` режиме `DATABASE_URL` обязателен.
- `CSRF_SECRET` и `SESSION_SECRET` должны быть ≥ 16 символов.

## 11. Границы — что НЕ входит в спецификацию

### 11.1 Исключено из MVP

| Элемент | Причина |
|---------|---------|
| Регистрация / восстановление пароля | Только mock-вход, нет БД пользователей |
| Встроенный чат | Сложно, не относится к ядру продукта |
| Видеозвонки | Сложно, не относится к MVP |
| Календарь и бронирование | За рамками демонстрации |
| Автоматический подбор наставников | Требует ML / правил |
| Полноценная админ-панель | За рамками MVP |
| Telegram-бот | Отложен до завершения основного веб-сценария |
| Мобильное приложение | Веб-адаптивность покрывает потребность |
| REST API (публичный) | API-спецификация в `docs/docs.json` — future-proof, не реализовано |
| Redis / кэш | Нет нагрузки, требующей кэширования |
| Микросервисы / Kubernetes | Команда из 2 человек, один моналит |
| Реальная OAuth2-интеграция (VK, Yandex) | Mock-вход, без API-вызовов |

| История прохождений кейсов | Low |

| Редактирование профиля ментора | Low |

## 14. Словарь терминов

| Термин | Определение |
|--------|------------|
| **Кейс** | Интерактивный сценарий с вопросами и вариантами ответов, проверяемый на сервере |
| **Roadmap** | Структурированный план обучения, представленный Markdown-файлом и JSON-диаграммой |
| **Попытка (Attempt)** | Состояние прохождения кейса одним пользователем, хранится в сессии |
| **Seed-данные** | Начальные данные (менторы, волонтёрские задачи), загружаемые при старте |
| **In-memory fallback** | Режим работы без PostgreSQL, с хранением данных в памяти процесса |
| **P2P-менторство** | Модель взаимопомощи, где студенты консультируют друг друга |
| **CSRF-токен** | Случайный токен, хранящийся в сессии и встраиваемый в формы для защиты от подделки |
| **Diagram.json** | JSON-файл с визуальной структурой roadmap (этапы, узлы, связи) |
| **Login Session** | Сессия авторизации: токен, роль, срок действия, CSRF-токен |
| **Mock-вход** | Демонстрационный вход без реальной аутентификации, редирект на ЛК |
