# ADR-0001: Серверный рендеринг на Go вместо SPA

**Статус:** Принят
**Владелец:** Tech Lead
**Обновлено:** 2026-11-13
**Дата решения:** 2026-11-05

## Контекст

MVP делает команда из двух студентов за ограниченное время. Платформа предназначена школьникам и студентам: страницы должны открываться быстро, работать на слабых устройствах, быть доступными с клавиатуры и скринридера и не требовать отдельной инфраструктуры сборки. Основной контент (roadmap, статьи, каталоги) почти статичен, интерактивность ограничена формами и одним сценарием кейса.

## Решение

Мы отдаём готовый HTML с сервера на Go (`net/http`, `chi`, `html/template`). Отдельного фронтенд-приложения и публичного REST API нет. JavaScript минимален и добавляет удобство, но не необходим (см. [ADR-0002](0002-htmx-progressive-enhancement.md)).

## Рассмотренные альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---------|-------|--------|------------------|
| SPA (React) и REST API | Богатая интерактивность, привычный стек | Две кодовые базы, сборка, состояние на клиенте, больше риска для доступности | Интерактивность MVP не оправдывает стоимость |
| Go-шаблоны + JS-фреймворк точечно | Гибко | Два способа рендеринга в одном проекте | Нет задач, которые HTMX не решает |

## Последствия

Плюсы: один язык и один процесс, быстрый старт, страницы работают без JS, проще доступность. Минусы: нет API для сторонних клиентов (см. [RFC-0001](../../rfc/0001-rest-api/README.md)); ошибки шаблонов видны только при рендере страницы, поэтому каждую страницу нужно открывать тестом (причина инцидента 2026-11-11, см. [постмортем](../../quality/postmortems/2026-11-11-lk-500.md)).
