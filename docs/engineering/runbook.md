# Runbook: GO-IT

**Статус:** Действует
**Владелец:** Backend
**Обновлено:** 2026-11-13

Инструкция по эксплуатации сервиса: запуск, проверка, диагностика, резервные копии. Проект учебный, SLO и дежурства не определены, поэтому runbook описывает, как быстро восстановить демонстрацию.

## Назначение и границы

GO-IT — один Go-процесс (`web`) и, в режиме с базой, PostgreSQL. Оператор отвечает за запуск, проверку здоровья и сохранность заявок. Вход и кабинеты намеренно открыты, не выставляйте сервис в открытую сеть ([SECURITY](../../SECURITY.md)).

## Зависимости

| Компонент | Зачем | Как проверить |
|-----------|-------|---------------|
| PostgreSQL 16 | Заявки, менторы, задачи (в режиме с `DATABASE_URL`) | `docker compose ps`: сервис `postgres` в состоянии `healthy`; `/health/ready` отвечает 200 |
| Файлы `templates/`, `static/`, `content/` | Страницы, статика, контент | Лежат рядом с бинарником (в образе копируются в `/app`) |
| Порт 8080 (`web`) и 5432 (`postgres`) | Доступ | `curl http://localhost:8080/health/live` |

## Запуск, остановка, обновление

```bash
cp .env.example .env              # один раз; замените пароли и SESSION_SECRET
docker compose up --build -d      # запуск
docker compose ps                 # оба сервиса должны быть Up, postgres — healthy
docker compose logs -f web        # журнал
docker compose down               # остановка, данные в томе сохраняются
```

Обновление: получите нужную версию (`git pull` или `git checkout <тег>`), затем `docker compose up --build -d`. Откат: `git checkout <предыдущая версия>` и та же команда. После любого перезапуска `web` сессии кейсов и форм сбрасываются: открытые формы нужно обновить.

Запуск без Docker: `make run` (хранилище в памяти, заявки пропадут при остановке).

## Проверка работоспособности

| Адрес | Ожидание |
|-------|----------|
| `GET /health/live` | `200`, тело `ok` |
| `GET /health/ready` | `200`; `503 not ready`, если PostgreSQL недоступна |
| `GET /` | `200`, страница главной |

В журнале при успешном старте: `connected to postgres` (или `using in-memory store`), затем `listening addr=:8080`. При остановке: `stopped`.

## Диагностика

| Симптом | Вероятная причина | Как проверить | Что делать |
|---------|-------------------|---------------|-----------|
| Контейнер `web` сразу завершается, в журнале `config err=…` | Короткий `SESSION_SECRET` (меньше 16 символов), в `production` оставлен секрет по умолчанию или нет `DATABASE_URL` | `docker compose logs web` | Исправить `.env`, перезапустить |
| `templates err=…` при старте | Запуск не из корня репозитория или нет папки `templates` | Текущий каталог, `ls templates` | Запускать из корня |
| `postgres err=…` при старте | БД не готова или неверная строка подключения | `docker compose ps`, значение `DATABASE_URL` | Дождаться `healthy`, исправить строку |
| `/health/ready` отвечает 503 | PostgreSQL недоступна | `docker compose ps`, `docker compose logs postgres` | Перезапустить `postgres`, проверить том и пароль |
| Заявки пропали после перезапуска | Сервер запущен без `DATABASE_URL`, в журнале `using in-memory store` | Журнал старта | Запускать через Compose или задать `DATABASE_URL` |
| Форма заявки или кейс отвечает 403 «Сессия устарела» | Сервер перезапускался после открытия страницы, истёк срок сессии (24 часа) или браузер блокирует cookie | В журнале строка `CSRF отклонён` с полем `причина` | Обновить страницу и отправить форму снова. Если причина «cookie сессии не получена»: проверить блокировку cookie в браузере и режим инкогнито |
| Страница roadmap или блога отвечает 500 «Что-то пошло не так» | Ошибка в `content/roadmaps/*.md`, `*.diagram.json` или статье | `go test ./internal/content` назовёт файл и поле | Исправить файл ([руководство по контенту](content-guide.md)) |
| Страница отвечает 500 с текстом «Не удалось отобразить страницу.» без оформления | Ошибка выполнения шаблона (отсутствует поле, неверный тип) | Запустить тест этой страницы, он покажет сообщение шаблона | Исправить шаблон |
| Порт занят (`listen err=…`) | Другой процесс использует 8080 | `HTTP_ADDR` | Задать другой порт |
| Память процесса растёт | Накопление сессий посетителей до истечения срока | Рост потребления без перезапусков | Перезапустить сервис; лимит числа сессий не реализован ([дорожная карта](../planning/roadmap.md)) |

Вход (`/auth`) и кабинеты (`/lk/…`) не используют cookie и сессии, поэтому 403 на них возникнуть не может ([ADR-0005](../architecture/adr/0005-demo-auth-without-state.md)).

## Резервное копирование и восстановление

Постоянные данные — только таблица заявок в PostgreSQL (`applications`); менторы и задачи пересоздаются из кода при старте.

```bash
# копия
docker compose exec -T postgres pg_dump -U goit goit > backup.sql
# восстановление в пустую базу
docker compose exec -T postgres psql -U goit goit < backup.sql
```

Восстановление проверяется запросом `select count(*) from applications;`.
