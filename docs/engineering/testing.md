# Стратегия тестирования

**Статус:** Действует
**Владелец:** QA
**Обновлено:** 2026-11-13

Документ описывает, что и чем проверяется, как запускать проверки и что остаётся на ручную проверку перед защитой. Он заменяет прежние QA-планы, часть которых описывала уже удалённые функции.

## Принципы

1. **Страница существует, пока её открывает тест.** Шаблоны не имеют проверки типов, поэтому каждая страница должна открываться хотя бы одним тестом, который проверяет ответ целиком (причина — [постмортем 2026-11-11](../quality/postmortems/2026-11-11-lk-500.md)).
2. **Замечание заказчика получает тест, который воспроизводит именно его.** Статус «выполнено» без такого теста не принимается ([правило](../standards/documentation-standard.md#8-правило-подтверждения-статусов)).
3. **Тесты работают на реальном роутере и шаблонах** (`httptest`, хранилище в памяти), а не на моках обработчиков.
4. **Документация проверяется так же, как код** ([`make docs-check`](#проверка-документации)).

## Уровни проверки

| Уровень | Чем | Где |
|---------|-----|-----|
| Модульные | Тесты пакетов `service`, `content`, `config`, `render` | `internal/*/…_test.go` |
| HTTP-интеграционные | Реальный роутер, шаблоны, сессии, хранилище в памяти | `internal/http/*_test.go` |
| Документация | Метаданные, ссылки, индексы, сверка маршрутов | `internal/docscheck`, `TestSpecificationListsEveryRoute` |
| Ручные | Браузер, клавиатура, скринридер, Docker, PostgreSQL | [Чек-лист](#ручной-регрессионный-чек-лист) |

Не автоматизировано: хранилище PostgreSQL, запуск `cmd/web`, поведение HTMX и вёрстка в браузере, доступность скринридером, `go test -race`.

## Запуск и покрытие

```bash
go test ./...                              # все тесты
go test -coverpkg=./... ./...              # покрытие по всем пакетам
make docs-check                            # только документация
make check-links                           # внешние ссылки (интернет)
```

Покрытие операторов на 2026-11-12: 75,9% (порог 70%). По пакетам: handlers 82%, content 89%, session 89%, service 88%, render 79%, catalog 86%; `repository/postgres` и `cmd/web` — 0%. Для настоящего покрытия обязателен ключ `-coverpkg=./...`: без него пакеты, которые проверяются из соседних, показывают заниженное значение.

## Соглашения

- Имя теста описывает ожидаемое поведение: `TestMentorDecisionsLiveInTheURL`, а не `TestMentor2`.
- Тест страницы проверяет статус, отсутствие `ZgotmplZ`, `<no value>` и ключевые элементы.
- Тест формы проверяет успех, ошибки у полей (422), CSRF (403) и сохранение введённых значений.
- Тест, закрывающий дефект, содержит в комментарии причину дефекта.
- Негативные тесты (мусор в полях, подмена параметров) обязательны для всего, что принимает данные из адреса или формы.

## Проверка документации

`make docs-check` проверяет по [стандарту](../standards/documentation-standard.md#10-автоматические-проверки): метаданные, ссылки и якоря, индексы, имена ADR, устаревшие имена. Тест `TestSpecificationListsEveryRoute` отдельно сверяет маршруты в [спецификации](../product/specification.md) с `router.go`.

## Критерий выхода перед защитой

Все автоматические тесты проходят; чек-лист пройден без критичных замечаний; найденные при проходе дефекты либо исправлены, либо записаны в [дорожную карту](../planning/roadmap.md) с обоснованием.
