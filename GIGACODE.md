## Проект

GO-IT — студенческий MVP образовательной платформы: кейсы, дорожные карты со схемой, каталоги менторов и волонтёрских задач, демонстрационный вход и три кабинета. Запускается локально, публичного деплоя нет. Go 1.22+, `html/template`, chi, HTMX, PostgreSQL (в разработке можно без БД).

## Обязательные правила работы

1. **Статус «готово» подтверждается запуском.** Перед тем как написать в документах «✅», открой затронутые страницы тестом и проверь ответ целиком ([DOC-STYLE §6](DOC-STYLE.md)). Тест на редирект или на наличие маршрута не доказывает, что страница открывается: в версии 1.8 четыре страницы кабинета отвечали 500 при «зелёных» тестах.
2. **Шаблон не доверяет данным.** Каждое поле, которое читает шаблон, должно существовать в структуре. Внутри `range` точка — это элемент списка, для данных страницы используй `$`.
3. **Не вводи новые inline-скрипты и `onclick`.** JS лежит в `static/js/`, страница должна работать без него (прогрессивное улучшение).
4. **Формы заявок и кейсы меняют состояние только POST с CSRF-токеном.** GET ничего не меняет (вход и кабинеты ничего не хранят, поэтому на них правило не распространяется). После POST — redirect (PRG) либо 422 с ошибками.
5. **Вход и кабинеты без состояния** (решение заказчика, REQ-002): никаких cookie, сессий, CSRF и проверок. Не добавляй их обратно без решения заказчика. Новые страницы кабинета добавляй через `lkRender` и `lkNav`; состояние демо-заявок живёт в параметре адреса `h`.
6. **Данные сессии копируются** (`Data.clone`). Сессия нужна кейсам и формам заявок. Новые карты и срезы внутри `session.Data` добавляй в `clone`, иначе будет гонка данных.
7. **Не показывай произвольный текст из адреса**: сообщения выбираются по коду (`lkFlash`).
8. **Документы и код меняются вместе** по таблице [DOC-STYLE §6](DOC-STYLE.md). Числа берутся из запуска.

## Команды

```bash
make run          # запуск (go run ./cmd/web)
make test         # go test ./...
make fmt          # gofmt
make compose      # docker compose up --build
make check-links  # проверка внешних ссылок roadmap (нужен интернет)
go test -coverpkg=./... ./...   # покрытие по всем пакетам
```

Для запуска тестов в среде без доступа к `proxy.golang.org` зависимости `golang.org/x/*` можно подключить через отдельный файл модуля (`go mod edit -modfile=… -replace`), основной `go.mod` не меняется.

## Как устроены ключевые части

- **Сессия** есть только у кейсов и форм заявок. Данные лежат в памяти процесса, в cookie — `<id>.<hmac>`. `Load` возвращает пустую сессию, если cookie нет, подпись неверна или срок вышел; в хранилище запись появляется только после `Save`. После перезапуска сервера открытые формы получают 403 (причина пишется в журнал через `Diagnose`). Страница 404 сессию не создаёт, HTML отдаётся с `no-store`.
- **Вход** — визуальная механика: `LoginPost` берёт роль из формы (`role`, приоритет у `quick`), проверяет её по белому списку и отвечает 303 на `/lk/<роль>`. Ничего не проверяется и не запоминается.
- **Кабинеты** открываются по адресу, без входа. Все страницы вызывают `lkRender`, который добавляет навигацию (`lkNav`) и `Page.LK` (скрывает шапку сайта). Данные условные; настоящий только каталог менторов. Решения по демо-заявкам хранятся в параметре `?h=1:accepted,2:declined` (разбор — `parseDecisions`). Настройки ученика проверяют формы, но ничего не сохраняют.
- **Кейсы.** Попытка (`AttemptState`) хранится в сессии; сервис проверяет порядок шагов и повтор. Результат содержит разбивку по темам.
- **Roadmap.** Markdown делится на введение и разделы; между ними схема из JSON. Формат и правила: [SPECIFICATION §9.1](SPECIFICATION.md). Нажатие на тему открывает `<dialog>`-панель, без JS работает справочник тем под схемой.
- **Ответ страницы** формируется в буфере: ошибка шаблона даёт 500, а не обрезанную страницу.

## Безопасность (кратко)

Формы заявок и кейсы: CSRF-токен, серверная проверка данных, подписанные сессии со сроком жизни. Везде: санитизация Markdown, параметризованные SQL, тело запроса до 1 МиБ, non-root в Docker, секреты из окружения (`SESSION_SECRET`). Вход и кабинеты намеренно ничего не защищают (демо): не выставляйте проект в открытую сеть. Открытые ограничения — в [PLAN.md](PLAN.md).
