# Руководство разработчика

**Статус:** Действует
**Владелец:** Tech Lead
**Обновлено:** 2026-11-13

Инструкция для тех, кто запускает проект, вносит изменения и проверяет их. Правила оформления изменений — в [CONTRIBUTING](../../CONTRIBUTING.md), устройство системы — в [обзоре архитектуры](../architecture/overview.md).

## Что нужно

| Инструмент | Версия | Зачем |
|-----------|--------|-------|
| Go | 1.22 или новее | Сборка и тесты |
| Docker и Docker Compose | любая актуальная | Запуск с PostgreSQL (по желанию) |
| make | любая | Короткие команды |

## Быстрый старт

Без базы данных (заявки хранятся в памяти процесса):

```bash
git clone <адрес репозитория>
cd GO-IT
make test
make run
```

Откройте `http://localhost:8080`. Запускайте команды из корня репозитория: шаблоны, статика и контент читаются по относительным путям.

С PostgreSQL через Docker Compose:

```bash
cp .env.example .env
docker compose up --build
```

## Переменные окружения

| Переменная | По умолчанию | Описание |
|-----------|-------------|----------|
| `APP_ENV` | `development` | Окружение. В `production` обязательны `DATABASE_URL` и собственный `SESSION_SECRET` |
| `HTTP_ADDR` | `:8080` | Адрес сервера |
| `DATABASE_URL` | пусто | Строка подключения к PostgreSQL. Пусто — хранилище в памяти |
| `SESSION_SECRET` | `dev-session-secret-change-me` | Ключ подписи cookie. Не короче 16 символов |
| `POSTGRES_PASSWORD` | `change_me` | Пароль БД для Docker Compose (используется только в `.env`) |

Файл `.env` не попадает в Git. Менять значения по умолчанию нужно в любом окружении, доступном другим людям.

## Команды

| Команда | Что делает |
|---------|-----------|
| `make run` | Запуск сервера (`go run ./cmd/web`) |
| `make test` | Все тесты, включая проверку документации |
| `make fmt` | Форматирование `gofmt` |
| `make compose` | `docker compose up --build` |
| `make docs-check` | Проверка документации по [стандарту](../standards/documentation-standard.md) |
| `make check-links` | Проверка внешних ссылок в схемах roadmap (нужен интернет) |
| `go test -coverpkg=./... ./...` | Тесты с покрытием по всем пакетам |

Перед коммитом выполните три проверки: `gofmt -l .` ничего не выводит, `go vet ./...` чистый, `go test ./...` проходит.

## Типичные задачи

### Добавить страницу

1. Добавьте обработчик в `internal/http/handlers/` и маршрут в `internal/http/router.go`.
2. Создайте шаблон `templates/pages/<имя>.html` с блоком `content`. В `range` используйте `$` для данных страницы: точка внутри `range` — элемент списка.
3. Добавьте строку маршрута в [спецификацию §8](../product/specification.md) (тест `TestSpecificationListsEveryRoute` проверит соответствие).
4. Напишите тест, который открывает страницу и проверяет ответ целиком: статус, отсутствие `ZgotmplZ` и `<no value>`, ключевые элементы.

### Добавить или изменить контент

См. [руководство по контенту](content-guide.md).

### Добавить поле в форму заявки

Поле нужно добавить в `domain.Application`, проверку — в `service.FieldErrors`, шаблон — в `templates/partials/application_form.html`, колонку — в миграцию (новый файл в `internal/repository/postgres/migrations/`), затем обновить тесты.

## Работа с шаблонами

- Один набор шаблонов на страницу, общий каркас — `layouts/base.html`. Страница определяет блок `content`.
- Ошибка в шаблоне видна только при выполнении. Отсутствующее поле даёт 500 именно на этой странице, поэтому каждая страница должна открываться тестом.
- Не добавляйте inline-скрипты и `onclick`: JS лежит в `static/js/`, страницы должны работать без него.
- Формы, меняющие состояние (заявки, кейсы), содержат `csrf_token`. Вход и кабинеты состояния не имеют ([ADR-0005](../architecture/adr/0005-demo-auth-without-state.md)).

## Отладка

- Журнал пишется в stdout в формате `ключ=значение`. Каждый запрос — строка `request` с полями `method`, `path`, `status`, `duration`, `request_id`.
- Отказ по CSRF записывается как `CSRF отклонён` с причиной. Расшифровка — в [runbook](runbook.md#диагностика).
- Страница вместо ошибки показывает «Не удалось отобразить страницу»: ищите ошибку шаблона, запустив тест страницы.

## Особенности среды без доступа к proxy.golang.org

Если зависимости `golang.org/x/*` не скачиваются, подключите их через отдельный файл модуля, не меняя `go.mod`:

```bash
cp go.mod /tmp/alt.mod && cp go.sum /tmp/alt.sum
go mod edit -modfile=/tmp/alt.mod -replace golang.org/x/net=github.com/golang/net@<версия из go.mod>
go test -modfile=/tmp/alt.mod ./...
```

Повторите `-replace` для `crypto`, `text` и `sync`.
