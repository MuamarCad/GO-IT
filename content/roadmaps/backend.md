# Backend на Go

Маршрут для тех, кто хочет понять сервер: запрос пришёл, данные проверили, ответ ушёл. Язык примера — Go, как в самом проекте GO-IT.

## Цель направления

Собрать небольшое HTTP-приложение: маршруты, шаблоны, валидация, запись в PostgreSQL, тесты ключевой логики. После маршрута вы сможете объяснить, почему итоговый балл кейса считается на сервере, а не в браузере.

## Базовые знания

- HTTP-методы: GET не меняет данные, POST — меняет.
- HTML-формы и шаблон Post/Redirect/Get.
- Что такое параметризованный SQL-запрос.
- Зачем нужны миграции схемы.

## Порядок тем

1. `net/http` и роутер (chi): путь, метод, 404.
2. `html/template`: экранирование, layout, части страницы.
3. Модель данных: структуры, slug, статусы заявки.
4. Сервис кейса: нельзя пропустить шаг, неизвестный вариант отклоняется.
5. PostgreSQL: таблица `applications`, seed каталогов.
6. Конфигурация через окружение, логирование без персональных данных.
7. Docker Compose: приложение + база на одной машине.

## Практические мини-проекты

- `GET /health/live` и `GET /health/ready`.
- Сохранение заявки ментору с проверкой, что наставник существует.
- Unit-тесты расчёта результата кейса.

## Критерии прогресса

- Сервер не доверяет баллу из браузера.
- Ошибка валидации понятна пользователю и не показывает SQL.
- После POST пользователь видит другую страницу (redirect).
- Тесты проходят командой `go test ./...`.
