# GO-IT: социальный код

Студенческий MVP образовательной платформы: знакомство с IT-профессиями через кейс, дорожные карты и демонстрационные каталоги взаимопомощи.

Публичный деплой не предусмотрен. Сайт запускается локально.

## Что внутри

- Главная и вкладки по макету: направления, первый кейс, менторы, волонтёрство, roadmaps, о проекте.
- Три наполненные дорожные карты (Frontend, Backend на Go, IT Project Manager).
- Один интерактивный кейс Frontend: ответы проверяет сервер на Go, результат с пояснениями и ссылкой на roadmap.
- Каталоги менторов и волонтёрских задач (seed) и форма заявки в PostgreSQL.
- Светлая / тёмная тема и режим повышенной контрастности.

Стек: Go, `html/template`, chi, HTMX (шаги кейса без перезагрузки, без JS работает как обычная форма), PostgreSQL, Docker Compose.

## Фронтенд

- `templates/layouts/base.html` — общий каркас; страницы в `templates/pages/` определяют только блок `content`; общие куски (шапка, подвал, логотип, форма заявки) — в `templates/partials/`.
- Дизайн-токены (палитра, шрифты) — в начале `static/css/app.css`. Источник: макет лендинга `draft/Main.dc.html`. Темы: светлая, тёмная, высокая контрастность (атрибуты `data-theme` и `data-contrast` на `<html>`).
- Шрифты Unbounded и Onest, а также HTMX лежат в `static/` (лицензии рядом), внешних CDN нет.
- `static/js/theme-init.js` подключается в `<head>` синхронно (применяет тему до отрисовки), `static/js/theme.js` — с `defer`.
- Кейс есть только у направления Frontend; у остальных направлений кнопка кейса скрыта (`CaseSlug: ""` в `internal/catalog`).

## Запуск через Docker Compose

```bash
cp .env.example .env
docker compose up --build
```

Откройте [http://localhost:8080](http://localhost:8080).

Приложение ждёт готовности Postgres, применяет миграции и наполняет seed-каталоги.

## Запуск без Docker

Нужны Go 1.22+ и (опционально) PostgreSQL. Без `DATABASE_URL` заявки хранятся в памяти процесса — удобно для вёрстки, для защиты используйте Compose.

```bash
make test
make run
```

## Сценарий демонстрации (5–7 минут)

1. Проблема: сложно выбрать IT-направление и понять повседневные задачи.
2. Главная: структура платформы и карточка шага кейса.
3. Кейс Frontend: четыре вопроса, сервер считает балл, дисклеймер «не диагноз профессии».
4. Roadmap Frontend (и при необходимости Backend / PM) — основной наполненный продукт.
5. Профиль ментора или волонтёрская задача: отправка заявки, `?sent=1`.
6. Переключение темы и контраста, фокус с клавиатуры.
7. Архитектура: handler → service → repository, тесты, Docker Compose.
