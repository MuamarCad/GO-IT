# Как собрать учебный pet-проект: границы важнее ambition

Дата: 2026-04-12

Pet-проект полезен, когда у него есть границы. GO-IT как пример: одно приложение на Go, несколько вкладок, один живой кейс, три дорожные карты, заявки в PostgreSQL.

## Что фиксировать в первый день

Прежде чем писать код, зафиксируйте три вещи:

1. **Стек, который уже знаете или обязаны показать.** Если вы учитесь на Go — используйте Go. Не нужно изучать новый язык для pet-проекта.
2. **Один сквозной сценарий, который можно показать за пять минут.** Пользователь → форма → ответ. Всё.
3. **Список того, чего не будет.** Деплой? Нет. Аккаунты? Нет. Бот? Нет.

Этот список — ваша защита от «scope creep». Вы знаете, чего НЕТ, и можете сосредоточиться на том, что есть.

## Пример структуры

```
go-it/
├── cmd/web/          # точка входа, сервер
├── internal/
│   ├── http/         # роуты и handlers
│   ├── service/      # бизнес-логика
│   ├── domain/       # типы и модели
│   └── content/      # markdown → HTML
├── content/
│   ├── blog/         # статьи
│   └── roadmaps/     # дорожные карты
└── go.mod
```

Каталог `internal/` — стандарт Go: код внутри него не импортируется извне. Это не ограничение, а сигнал: «это внутренняя логика, а не публичный API».

## Сквозной сценарий: от формы к результату

Pet-проект должен иметь один основной сценарий. В GO-IT это:

```
Пользователь открывает /cases/frontend
→ отвечает на вопросы (сохраняется в сессии)
→ видит результат
→ переходит на roadmap
→ читает roadmaps и начинает обучение
```

Каждый шаг — отдельный handler. Каждый handler — отдельный кусок логики. Но всё связано: пользователь, сессия, данные, шаблон.

### Handler: точка входа

```go
func (s *Server) CaseStart(w http.ResponseWriter, r *http.Request) {
    slug := chi.URLParam(r, "slug")
    state, view, err := s.CaseSvc.Start(slug)
    if err != nil {
        s.NotFound(w, r)
        return
    }
    s.Render.HTML(w, "case_question.html", render.Page{
        Title:  view.Case.Title + " — GO-IT",
        Data:   view,
    }, http.StatusOK)
}
```

Handler — это тонкий слой. Он не содержит логики. Он получает запрос → вызывает сервис → рендерит шаблон. Всё.

### Service: бизнес-логика

```go
func (s *CaseService) Start(slug string) (domain.AttemptState, domain.QuestionView, error) {
    c := s.cases[slug]
    state := domain.AttemptState{Slug: slug, Index: 0}
    return state, questionView(c, 0), nil
}
```

Service — это «мозг». Он знает про кейсы, вопросы и ответы. Он не знает про HTTP, шаблоны и базы данных.

## Сервер: минимум для демонстрации

Вам не нужен Docker Compose, Kubernetes или CI/CD для pet-проекта. Вот минимальный набор:

```go
r := chi.NewRouter()
r.Get("/", s.Home)
r.Get("/cases/{slug}", s.CaseStart)
r.Post("/cases/{slug}/answer", s.CaseAnswer)
r.Get("/cases/{slug}/result", s.CaseResult)
r.Get("/blog", s.Blog)
r.Get("/blog/{slug}", s.Article)
http.ListenAndServe(":8080", r)
```

Шесть маршрутов. Пять handlers. Один router. За пять минут — работает.

## База данных: когда нужна, когда нет

В GO-IT база данных нужна для заявок (申请ы на менторство). Для кейсов — нет: достаточно in-memory.

Правило: если данные должны сохраниться после перезапуска сервера — нужна БД. Если данные живут в рамках сессии пользователя — достаточно памяти.

### In-memory для dev

```go
type memoryRepo struct {
    mu    sync.Mutex
    data  map[string]domain.CareerCase
}
```

`sync.Mutex` защищает данные от race-conditions. Для dev-режима достаточно.

### PostgreSQL для prod

```go
pool, _ := pgxpool.New(ctx, os.Getenv("DATABASE_URL"))
```

`pgxpool` — connection pool для PostgreSQL. Параметризованные запросы `$1`, `$2` — защита от SQL-инъекций.

## Шаблоны: SSR без фреймворков

GO-IT использует `html/template` — встроенный шаблонизатор Go. Нет webpack, нет React, нет SPA. Всё рендерится на сервере.

```html
<!-- case_question.html -->
<h1>{{ .Case.Title }}</h1>
<p>{{ .Question.Text }}</p>
<form method="POST" action="/cases/{{ .Case.Slug }}">
  {{ range .Question.Options }}
  <label>
    <input type="radio" name="option" value="{{ .ID }}">
    {{ .Text }}
  </label>
  <small>{{ .Explanation }}</small>
  {{ end }}
  <button type="submit">Ответить</button>
</form>
```

Простой HTML с встроенной логикой Go. Никаких бандлеров, никаких компиляций на клиенте.

## Чек-лист pet-проекта

- [ ] Один стэк: Go + Chi + PostgreSQL
- [ ] Один сквозной сценарий: форма → ответ → результат
- [ ] Сервер запускается одной командой: `make run`
- [ ] Шаблоны SSR: html/template
- [ ] Тесты: handler → service → repo
- [ ] Graceful shutdown: корректное завершение за 8 секунд
- [ ] Документация: README с командой запуска

## Практические советы

### Начните с /live

Первая страница — health-check. Если `/live` возвращает "ok", сервер работает. Дальше — добавляете маршруты.

### Не оптимизируйте заранее

Не нужно кэшировать, не нужно микросервисы, не нужно rate-limiting. Pet-проект — для обучения, не для production. Добавьте оптимизацию только когда увидите реальную проблему.

### Версия — это не фича

Не нужно версионировать API, не нужно A/B тесты, не нужно feature flags. Версия — это решение для команды, не для одного человека.

### Тестировать — нужно

Хотя бы один тест на сервис: Start → Get → Answer → Result. Это не покрытие для галочки. Это ваш способ убедиться, что логика работает при изменении кода.

## Что делать, если застряли

### «Не знаю, что сделать»

Возьмите кейс GO-IT. Он уже содержит контент. Ваша задача — подключить его к серверу, а не придумать заново.

### «Не знаю, как начать»

1. Скопируйте структуру GO-IT.
2. Замените кейсы на свои.
3. Добавьте один маршрут.
4. Запустите.
5. Повторите.

### «Не получается запустить»

Проверьте:
- `go mod tidy` — зависимости собраны.
- `go run cmd/web/main.go` — сервер стартовал.
- `curl localhost:8080/live` — возвращает "ok".

## Заключение

Pet-проект — это не приложение для продакшена. Это способ проверить, нравится ли вам направление. Если за две недели вы сделали работающий маршрут — вы уже прошли больше, чем те, кто десять раз начинал и не закончил.

GO-IT показывает, что pet-проект может быть живым: с кейсами, дорожными картами, статьями в блоге и заявками на менторство. Не идеальным. Но живым.

Начните с `/live`. Остальное — по ходу.
