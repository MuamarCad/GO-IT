## 6. Дополнение 12.11.2026: «403 Сессия устарела» при входе

Участник команды сообщил, что вход иногда завершается ошибкой 403. Воспроизведено на запущенном сервере: ошибка возникает, когда между открытием страницы входа и отправкой формы сервер перезапускался. Сессии хранятся в памяти процесса, токен в открытой форме после перезапуска недействителен. Само по себе поведение корректно, но оно заканчивалось тупиковой страницей ошибки. Это не дефект браузера.

| # | Изменение |
|---|-----------|
| 1 | Вход при устаревшем токене показывает форму заново со свежим токеном и пояснением (код 403 сохранён), повторное нажатие «Войти» работает (FR-85) |
| 2 | Каждый отказ по CSRF пишется в журнал с причиной: нет cookie, чужая подпись, сессия неизвестна (перезапуск или срок), токен не совпал |
| 3 | Страница 404 не создаёт сессию: раньше запрос иконок или служебных адресов без cookie мог перезаписать cookie открытой страницы входа (NFR-24) |
| 4 | HTML-страницы отдаются с `Cache-Control: no-store`, чтобы кнопка «Назад» не показывала форму с устаревшим токеном (NFR-23) |

Остаётся ограничение: после перезапуска сервера все вошедшие пользователи выходят из кабинетов. Для демо это допустимо, постоянное хранение сессий вынесено в [дорожной карте](../../planning/roadmap.md) (P2).

## 7. Решение владельца проекта 12.11.2026: вход без проверок, cookie и сессий

После обновления вход продолжал не работать, а причину («403 Сессия устарела») нельзя было надёжно устранить, пока вход зависит от cookie. Владелец проекта решил: для демонстрации достаточно визуальной механики, выбор кабинета и переход в него должны просто работать.

| Что изменено | Подробности |
|--------------|-------------|
| Вход | `POST /auth` и `/auth/{provider}` (GET и POST) ведут в `/lk/<роль>` при любом содержимом формы; роль по белому списку, адрес перехода из фиксированных путей. Cookie, сессия и CSRF не создаются (проверено на запущенном сервере: `Set-Cookie` отсутствует) |
| Кабинеты | Открываются по адресу без входа. Убраны `lkGuard`, ролевой доступ, выход через POST. «Выйти» — ссылка на `/` |
| Заявки | «Принять» и «Отклонить» стали ссылками, решение хранится в параметре `?h=…`. Неизвестные значения игнорируются, текст из адреса не выводится |
| Настройки ученика | Проверка форм сохранена, данные не сохраняются, CSRF и сессия не нужны |
| Сессии | Остались только у кейсов и форм заявок. Удалены `LoggedIn`, `Role`, `Profile`, `Handled`, `Rotate`, `Clear` |
| Документы | SPEC 2.2 (FR-70…82, §3.4, §8), README, GIGACODE 2.1, PLAN 2.1. Тест `TestSpecificationListsEveryRoute` теперь проверяет и лишние маршруты в документе |

Последствия: SEC-11 (роли) и SEC-12 (CSRF входа) закрыты удалением самой механики, SEC-09 и SEC-10 остаются актуальны для сессий кейсов и форм (подпись и срок жизни сохранены). Число тестов уменьшилось с 78 до 56: удалены проверки ролей, ротации и входа с CSRF, функций больше нет; проверки страниц кабинетов, настроек, заявок и сессий кейсов сохранены. Проект нельзя выставлять в открытую сеть: любой посетитель может открыть любой кабинет.
