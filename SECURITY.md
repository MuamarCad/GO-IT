# Безопасность

**Статус:** Действует
**Владелец:** Tech Lead
**Обновлено:** 2026-11-13

Что проект защищает, чего намеренно не защищает и как сообщить о проблеме. Проект учебный: его нельзя выставлять в открытую сеть в нынешнем виде.

## Область

Демонстрационное веб-приложение. Данные пользователей: текст заявок (имя, контакт, сообщение). Реальных учётных записей, паролей и платежей нет.

## Намеренные ограничения

| Ограничение | Почему | Что делать при реальном использовании |
|-------------|--------|--------------------------------------|
| Вход и кабинеты открыты: роль выбирается без проверок, любой посетитель открывает любой кабинет | Решение владельца проекта для демонстрации ([ADR-0005](docs/architecture/adr/0005-demo-auth-without-state.md)) | Реализовать настоящую аутентификацию и авторизацию (новый ADR и RFC) |
| Данные кабинетов условные | Демонстрация | Подключить хранилище и права доступа |
| Нет TLS, у cookie нет флага `Secure` | Локальный запуск по HTTP | Терминировать TLS на прокси и включить `Secure` |
| Нет ограничения частоты запросов | Локальный запуск | Добавить rate-limit на формы |
| Нет ограничения числа сессий в памяти | Срок жизни сессий снижает риск | Ограничить число или вынести сессии |
| Seed перезаписывает записи при каждом старте | Технический долг | Seed без перезаписи изменённых записей |
| Менторы, задачи и контент отдаются всем | Публичный каталог | — |

## Реализованные меры

| Мера | Где |
|------|-----|
| CSRF-токен в формах кейсов и заявок, проверка на сервере | `internal/session`, обработчики |
| Подписанный cookie сессии (HMAC-SHA256), срок жизни 24 часа, глубокое копирование данных сессии | `internal/session` |
| Серверная проверка всех пользовательских данных | `internal/service`, `internal/http/handlers` |
| Санитизация Markdown (bluemonday), автоматическое экранирование шаблонов | `internal/content`, `html/template` |
| Параметризованные SQL-запросы | `internal/repository/postgres` |
| Ограничение размера запроса 1 МиБ | `internal/http/handlers` (`LimitBody`) |
| Адрес перехода при входе строится из фиксированных путей по белому списку ролей | `internal/http/handlers/auth.go` |
| Ошибки не раскрывают SQL и стек, отказы CSRF пишутся в журнал с причиной | обработчики, `session.Diagnose` |
| Пользователь без прав в контейнере, секреты из окружения, проверка `SESSION_SECRET` | `Dockerfile`, `internal/config` |
| Страницы с токенами отдаются с `Cache-Control: no-store` | `internal/http/render` |

## Рекомендации по эксплуатации

- Меняйте `SESSION_SECRET`, `POSTGRES_PASSWORD` и строку `DATABASE_URL` в `.env`. Файл `.env` не коммитится.
- Не публикуйте порт 5432 за пределы машины.
- Не размещайте проект в открытой сети, пока не реализована настоящая аутентификация.

## Как сообщить об уязвимости

Публичного канала у проекта нет. Сообщите авторам напрямую (контакты — в учебной группе), не создавая публичных записей с подробностями эксплуатации. Укажите: что обнаружено, как воспроизвести, какое влияние. Подтверждённые проблемы фиксируются в [отчёте аудита](docs/quality/audits/2026-11-11-audit.md) или новом отчёте и исправляются с тестом.
