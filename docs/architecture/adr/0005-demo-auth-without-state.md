# ADR-0005: Демонстрационный вход без проверок, cookie и сессий

**Статус:** Принят
**Владелец:** Tech Lead
**Обновлено:** 2026-11-13
**Дата решения:** 2026-11-12

## Контекст

Требование заказчика REQ-002 п.1: пропускать в выбранный кабинет даже с пустыми полями. Первая реализация делала вход «настоящим» (роли, подписанные сессии, ротация, CSRF), но при проверке команды он продолжал давать 403 «Сессия устарела», а настоящей аутентификации в проекте всё равно нет.

## Решение

Вход — визуальная механика: роль берётся из формы по белому списку и превращается в `303` на `/lk/<роль>`. Кабинеты открываются по адресу, не используют cookie, сессии и CSRF и показывают условные данные. Решения по демо-заявкам хранятся в параметре адреса `?h=`. Решение принял владелец проекта 2026-11-12; оно заменяет ролевую реализацию от 2026-11-11.

## Рассмотренные альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---------|-------|--------|------------------|
| Настоящая аутентификация (учётные записи, пароли) | Реалистичный сценарий | Хранилище пользователей, восстановление пароля, отдельные риски | Вне границ MVP |
| Сессионный вход с ролями (был реализован) | Ближе к настоящему | Зависит от cookie, давал сбои при проверке | Владелец проекта отказался |

## Последствия

Плюсы: вход работает всегда, нет состояния и поверхности атаки по сессиям. Минусы: любой посетитель открывает любой кабинет, поэтому проект нельзя выставлять в открытую сеть (описано в [SECURITY](../../../SECURITY.md)); решения по заявкам видны только в адресе. Если потребуется настоящий вход, создаётся новый ADR и RFC.
