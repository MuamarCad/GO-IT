## Проект

GO-IT — студенческий MVP образовательной платформы: кейсы, дорожные карты со схемой, каталоги менторов и волонтёрских задач, демонстрационный вход и три кабинета. Запускается локально, публичного деплоя нет. Go 1.22+, `html/template`, chi, HTMX, PostgreSQL (в разработке можно без БД).

## Обязательные правила работы

1. **Статус «готово» подтверждается запуском.** Перед записью «✅» в документе откройте затронутые страницы тестом и проверьте ответ целиком. Тест на редирект или наличие маршрута не доказывает, что страница открывается ([постмортем](docs/quality/postmortems/2026-11-11-lk-500.md)).
2. **Числа берутся из запуска**, а не из памяти: тесты, покрытие, число маршрутов, вопросов, тем.
3. **Шаблон не доверяет данным.** Каждое поле, которое читает шаблон, должно существовать в структуре. Внутри `range` точка — элемент списка, для данных страницы используйте `$`.
4. **Не добавляйте inline-скрипты и `onclick`.** JS лежит в `static/js/`, страница работает без него.
5. **Вход и кабинеты без состояния** ([ADR-0005](docs/architecture/adr/0005-demo-auth-without-state.md)): никаких cookie, сессий, CSRF и проверок. Не добавляйте их без решения владельца проекта. Новые страницы кабинета добавляйте через `lkRender` и `lkNav`; решения по демо-заявкам хранятся в параметре адреса `h`.
6. **Формы заявок и кейсы** меняют состояние только `POST` с CSRF-токеном и завершаются редиректом или ответом 422. Сессия нужна только им; новые карты и срезы внутри `session.Data` добавляйте в `clone`, иначе будет гонка данных.
7. **Не показывайте произвольный текст из адреса**: сообщения выбираются по коду (`lkFlash`).
8. **Документы и код меняются вместе** по [таблице стандарта](docs/standards/documentation-standard.md#6-что-и-когда-обновлять). Новый маршрут попадает в спецификацию §8 (тест сверит). Значимое решение оформляется ADR.
9. **Не копируйте чужие материалы.** Структуру roadmap.sh копировать нельзя, внешние ресурсы только ссылками.
10. **Ничего не придумывайте в документах:** если факт не проверен, записывайте «не проверено» с причиной.

## Команды

```bash
make test         # тесты, включая проверку документации
make fmt          # gofmt
make run          # запуск
make docs-check   # проверка документации
make check-links  # внешние ссылки roadmap (нужен интернет)
go test -coverpkg=./... ./...   # покрытие по всем пакетам
```

Перед завершением работы: `gofmt -l .` пусто, `go vet ./...` чистый, `go test ./...` проходит, `make docs-check` проходит. Подробности и обходной путь для среды без доступа к `proxy.golang.org` — в [руководстве разработчика](docs/engineering/development.md).

## Быстрая карта кода

`cmd/web` — точка входа. `internal/http/handlers` — страницы и заявки (`handlers.go`), вход (`auth.go`), кабинеты (`lk.go`). `internal/http/render` и `templates/` — шаблоны. `internal/service` — логика кейсов и заявок. `internal/content` — Markdown и схемы roadmap. `internal/cases`, `internal/catalog` — кейсы и начальные данные. `internal/session` — сессии кейсов и форм. Полная таблица — в [обзоре архитектуры](docs/architecture/overview.md#слои-и-пакеты).
