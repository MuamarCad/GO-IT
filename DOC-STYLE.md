# Стандарт документации GO-IT

**Версия:** 1.0
**Дата:** 10 ноября 2026
**Статус:** Действующий

---

## 1. Назначение

Этот документ определяет структуру, формат и правила оформления всей проектной документации GO-IT.

**Цель:** обеспечить согласованность, избежать дублирования информации и позволить любому участнику (или AI-агенту) быстро найти нужную информацию.

---

## 2. Файловая структура документации

```
GO-IT/
├── README.md              # Пользователь: быстрый старт, обзор
├── SPECIFICATION.md       # Разработчик: требования, сценарии, acceptance criteria
├── PLAN.md                # Команда: дорожная карта, фазы, риски, метрики
├── GIGACODE.md            # AI-агент: полный контекст для автономной работы
├── docs/
│   └── docs.json          # OpenAPI спецификация (future REST API)
└── draft/                 # Черновики, макеты, презентации (не часть производства)
```

---

## 3. Роли документов

### 3.1 `README.md` — Пользовательское руководство

**Целевая аудитория:** новые пользователи, преподаватель на защите.

**Содержание:**

| Секция | Содержание |
|--------|-----------|
| Заголовок + один абзац | Что делает проект, для кого, статус (MVP, локальный) |
| Что внутри | Краткий обзор ключевых функций (3-5 пунктов) |
| Стек | Технологии в одном абзаце или маркированном списке |
| Фронтенд | Только что важно для понимания UI: шаблоны, темы, шрифты, HTMX |
| Запуск через Docker Compose | `cp .env.example .env` → `docker compose up --build` → URL |
| Запуск без Docker | `go 1.22+`, опционально PostgreSQL, команды `make` |
| Сценарий демонстрации | Пошаговый сценарий для защиты (5-7 минут) |
| Проверки перед защитой | Чек-лист с `[ ]` |
| Команды | Справочник `make` команд |

**Правила:**

- **Не содержит:** маршрутов, деталей архитектуры, моделей данных, требований
- **Не содержит:** детальных описаний тестов, безопасности, технического долга
- **Не содержит:** плана развития, метрик, рисков
- **Длина:** ≤ 80 строк
- **Перекрёстные ссылки:** на `SPECIFICATION.md` (детали), `PLAN.md` (дорожная карта)

### 3.2 `SPECIFICATION.md` — Спецификация проекта

**Целевая аудитория:** разработчики, тестировщики, PM.

**Содержание:**

| Секция | Содержание |
|--------|-----------|
| Метаданные | Версия, дата, проект, статус |
| 1. Назначение | Зачем нужен проект, для кого |
| 2. Область применения | Целевые аудитории, сценарии использования |
| 3. Пользовательские сценарии | Диаграммы обмена сообщениями, требования |
| 4. Функциональные требования | Таблица с ID, описанием, приоритетом, статусом |
| 5. Модель данных | Доменные типы, схема БД, контент, seed-данные |
| 6. Нефункциональные требования | Производительность, безопасность, надёжность, тесты |
| 7. Архитектура | Только общая схема (ASCII-диаграмма), без деталей пакетов |
| 8. Маршруты | Все маршруты сгруппированы по доменам |
| Приложения | Чек-листы готовности |

**Правила:**

- **ID требований:** `FR-NNN` (функциональные), `NFR-NNN` (нефункциональные)
- **Приоритеты:** `Must`, `Should`, `Could`, `Won't` (MoSCoW)
- **Статусы:** `✅ Реализовано`, `❌ Не реализовано`, `⚠️ Частично`
- **Не содержит:** плана развития, технического долга, деталей пакетов
- **Не содержит:** команд `make`, инструкций по запуску
- **Не содержит:** информации для AI-агентов
- **Длина:** без ограничений, но без воды

### 3.3 `PLAN.md` — План развития

**Целевая аудитория:** команда разработки, менеджер проекта.

**Содержание:**

| Секция | Содержание |
|--------|-----------|
| 1. Контекст проекта | Назначение, текущий статус (ссылка на SPEC), целевая аудитория |
| 2. Цели развития | Главная цель + измеримые цели с метриками |
| 3. Текущее состояние | Реализовано / не реализовано / техдолг / пробелы безопасности |
| 4. План развития | Фазы с задачами, зависимостями, критериями завершения |
| 5. Приоритеты и зависимости | Матрица приоритетов, блокеры |
| 6. Риски | Технические, процессные, качества, mitigation |
| 7. Отложенные улучшения | Backlog |
| 8. Метрики успеха | Количественные (таблица с текущим/целевым) и качественные |
| 9. Источники и ссылки | Таблица документов |
| 10. Изменения | Лог версий |
| Приложение A | Чек-лист готовности к защите |

**Правила:**

- **Фазы:** каждая фаза имеет цель, задачи с зависимостями, deliverable, критерии завершения
- **Задачи:** формат `X.Y` (Фаза.Задача), зависит от предыдущих задач
- **Риски:** вероятность (Низкая/Средняя/Высокая), влияние, mitigation
- **Метрики:** колонки «Текущее», «Цель», «Приоритет»
- **Не содержит:** деталей реализации, маршрутов, моделей данных
- **Не содержит:** пользовательских инструкций по запуску

### 3.4 `GIGACODE.md` — Контекст для AI-агента

**Целевая аудитория:** AI-агенты (GigaCode, и др.).

**Содержание:**

| Секция | Содержание |
|--------|-----------|
| Directory Overview | Путь, статус, назначение проекта |
| Key Files | Таблица всех ключевых файлов сpurpose |
| Project Architecture | Схема слоёв, пакеты (таблица с файлами/строками), маршруты |
| Building and Running | Docker Compose, без Docker, pre-launch checklist |
| Dependencies | go.mod зависимости |
| Frontend Architecture | Шаблоны, CSS, JS, шрифты, diagram.json |
| Data Storage | PostgreSQL schema, markdown/json контент, режимы БД |
| Testing | Файлы тестов, покрытие, что не протестировано |
| Security Features | Таблица мер безопасности |
| Development Conventions | Стиль, CI/CD, линтеры, паттерны |
| Known Gaps & Technical Debt | Все известные проблемы с номерами |
| Draft Artifacts | Что в `draft/`, назначение |
| API Documentation | Ссылка на `docs/docs.json` |
| Quick Reference | ENV-переменные, seed-данные, количество шаблонов/ассетов |

**Правила:**

- **Максимально подробный:** содержит всю информацию, необходимую AI для автономной работы
- **Конкретные числа:** количество файлов, строк, тестов, маршрутов
- **Таблицы для справочных данных:** маршруты, seed-данные, шаблоны, зависимости
- **Не содержит:** плана развития, пользовательских сценариев защиты
- **Не содержит:** высокоуровневых описаний без деталей

### 3.5 `docs/docs.json` — OpenAPI спецификация

**Содержание:** OpenAPI 3.0.3 для будущего REST API.

**Правила:**

- Не реализован (future state)
- Упоминание в других документах только как ссылка
- **Не дублировать** маршруты из `SPECIFICATION.md`

### 3.6 `draft/` — Черновики

**Содержание:** концепции, макеты, презентации, PDF.

**Правила:**

- Не входит в production
- Упоминание в `GIGACODE.md` как «артефакты для контекста»
- **Не ссылаться** из `README.md`, `SPECIFICATION.md`, `PLAN.md`

## 4. Стандарты оформления

### 4.1 Метаданные

Каждый документ (кроме `docs.json`) начинается с заголовка и блока метаданных:

```markdown
# Название

**Версия:** X.Y
**Дата:** [дата]
**Проект:** GO-IT — краткое описание
**Статус:** [Действующий | Черновик | Устарел]
```

### 4.2 Нумерация требований

| Префикс | Тип | Диапазон |
|---------|-----|----------|
| `FR-` | Функциональные требования | 01–99 |
| `NFR-` | Нефункциональные требования | 01–99 |
| `TD-` | Технический долг (в PLAN.md) | 1–99 |
| `SEC-` | Пробелы безопасности (в PLAN.md) | 1–99 |
| `C-` | Цели (в PLAN.md) | 1–99 |
| `D-` | Задачи (в PLAN.md) | X.Y формат |

### 4.3 Приоритеты (MoSCoW)

| Приоритет | Значение | Символ |
|-----------|----------|--------|
| `Must` | Обязательно для MVP / защиты | 🔴 |
| `Should` | Важно, но можно отложить | 🟡 |
| `Could` | Желательно, если останется время | 🟢 |
| `Won't` | Не в рамках текущего спринта/семестра | 🔵 |

### 4.4 Статусы реализации

| Статус | Значение | Формат |
|--------|----------|--------|
| ✅ Реализовано | Полностью работает | `✅ Реализовано` |
| ❌ Не реализовано | Не начато | `❌ Не реализовано` |
| ⚠️ Частично | Работает наполовину | `⚠️ Частично / N%` |

### 4.5 Перекрёстные ссылки

Ссылки между документами в формате `[имя](путь)`:

| Откуда | Куда | Формат |
|--------|------|--------|
| README → SPECIFICATION | Детали требований | `[Спецификация](SPECIFICATION.md)` |
| README → PLAN | Дорожная карта | `[План развития](PLAN.md)` |
| SPEC → GIGACODE | Детали архитектуры | `[Контекст для AI](GIGACODE.md)` |
| PLAN → SPEC | Исходные требования | `[Спецификация](SPECIFICATION.md)` |

### 4.6 Таблицы

- Заголовки таблиц на русском языке
- Сортировка: по ID (если есть), затем по алфавиту
- Максимум 3 колонки для простоты чтения в терминале
- Длинные таблицы (маршруты) разбивать по доменам

### 4.7 Код и команды

- Команды оболочки: `backtick` для коротких, блок для многострочных
- Пути файлов: `backtick`
- Имена функций/типов: `backtick`
- Числа: `backtick` если являются параметрами (port 8080, Go 1.22)

### 4.8 Язык

- Основной язык: **русский**
- Технические термины, имена функций, пути — на английском (`backtick`)
- Логи, stack traces, JSON-ключи — без перевода

## 5. Правила согласованности

### 5.1 Единый источник правды

| Тема | Где один источник | Где только ссылаться |
|------|-------------------|---------------------|
| Маршруты | `SPECIFICATION.md` (секция 8) | `GIGACODE.md` (копировать, не переписывать) |
| Модель данных | `SPECIFICATION.md` (секция 5) | `GIGACODE.md` |
| Статусы реализации | `SPECIFICATION.md` | `PLAN.md`, `README.md` |
| Технический долг | `PLAN.md` (секция 3.3) | `GIGACODE.md` |
| Seed-данные | `SPECIFICATION.md` (секция 5.4) | `GIGACODE.md`, `README.md` |

### 5.2 Версионирование

- Все документы синхронизируются вместе
- При изменении одного — проверка согласованности остальных
- Лог изменений в каждом документе

### 5.3 Проверка перед коммитом

При изменении документации:

1. `[ ]` Новый документ соответствует шаблону (секция 4)
2. `[ ]` Нет дублирования информации между документами
3. `[ ]` Перекрёстные ссылки актуальны
4. `[ ]` Статусы реализации совпадают во всех документах
5. `[ ]` ID требований не изменены, новые нумеруются корректно

## 6. Чек-лист при обновлении документации

При любом изменении проекта обновить:

| Изменение в коде | Обновить документ |
|-----------------|-------------------|
| Новый маршрут | `SPECIFICATION.md` (секция 8), `GIGACODE.md` |
| Новый доменный тип | `SPECIFICATION.md` (секция 5.1), `GIGACODE.md` |
| Изменение требований | `SPECIFICATION.md`, `PLAN.md` (статусы) |
| Новый план/фаза | `PLAN.md` |
| Новый тест | `GIGACODE.md` (секция Testing) |
| Новый файл | `GIGACODE.md` (Key Files) |
| Исправление бага | `PLAN.md` (Known Gaps) |
| Запуск / команды | `README.md` |
