# ADR-0007: Два хранилища за интерфейсами и встроенные миграции

**Статус:** Принят
**Владелец:** Tech Lead
**Обновлено:** 2026-11-13
**Дата решения:** 2026-11-05

## Контекст

Разработка и демонстрация должны запускаться без базы, а защита — с PostgreSQL. Заявки должны переживать перезапуск в режиме с базой.

## Решение

Сервисы и обработчики зависят от интерфейсов (`ApplicationStore`, `TargetChecker`, `Catalog`). Есть реализации `memory` (по умолчанию, если `DATABASE_URL` пуст) и `postgres` (драйвер `pgx`). SQL-миграции встроены в бинарник (`go:embed`) и применяются при старте.

## Рассмотренные альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---------|-------|--------|------------------|
| Только PostgreSQL | Одно поведение | Нельзя быстро запустить без Docker | Тормозит разработку |
| ORM | Меньше SQL | Зависимость и магия | Запросов мало, SQL прозрачнее |

## Последствия

Плюсы: быстрый запуск, тесты на памяти, простой деплой. Минусы: две реализации нужно держать согласованными; `postgres` не покрыт автоматическими тестами (0%), см. [дорожную карту](../../planning/roadmap.md).
