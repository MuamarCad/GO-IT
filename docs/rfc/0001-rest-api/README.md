# RFC-0001: Публичный REST API

**Статус:** Отложен
**Владелец:** Системный аналитик
**Обновлено:** 2026-11-13

Предложение описывает версионируемый REST API для чтения каталогов и отправки заявок. Черновик контракта в формате OpenAPI 3.0.3 лежит рядом: [openapi.draft.json](openapi.draft.json). В MVP API не реализуется ([ADR-0001](../../architecture/adr/0001-server-side-rendering.md)), поэтому RFC отложен.

## Проблема и мотивация

Сейчас данные доступны только через HTML-страницы. Сторонний клиент (Telegram-бот, мобильное приложение, виджет партнёра) не может получить каталоги или оставить заявку, не разбирая HTML. Требований заказчика на такие клиенты пока нет, поэтому мотивация гипотетическая.

## Цели и не-цели

Цели: стабильный контракт для чтения кейсов, менторов, волонтёрских задач, материалов и статей; отправка заявки на волонтёрскую задачу и прохождение кейса.

Не-цели: настоящая аутентификация, админские операции, замена серверного рендеринга.

## Предложение

Черновик контракта содержит 13 операций под префиксом `/api/v1`:

| Метод | Путь | Назначение |
|-------|------|-----------|
| GET | `/api/v1/health` | Проверка здоровья |
| GET | `/api/v1/cases`, `/api/v1/cases/{caseId}` | Каталог и карточка кейса |
| POST | `/api/v1/cases/{caseId}/attempts` | Прохождение кейса |
| GET | `/api/v1/mentors`, `/api/v1/mentors/{mentorId}` | Каталог и карточка ментора |
| GET | `/api/v1/volunteer/opportunities`, `/api/v1/volunteer/opportunities/{opportunityId}` | Каталог и карточка задачи |
| POST | `/api/v1/volunteer/requests` | Отклик на задачу |
| GET | `/api/v1/resources`, `/api/v1/resources/{resourceId}` | Материалы |
| GET | `/api/v1/articles`, `/api/v1/articles/{articleId}` | Статьи |

Черновик был составлен до текущих решений и не синхронизирован с кодом: имена сущностей (`resources`, `opportunities`) отличаются от доменных типов проекта, роадмапов в нём нет.

## Альтернативы

| Вариант | Плюсы | Минусы |
|---------|-------|--------|
| Ничего не делать | Нет затрат и новой поверхности атаки | Нет сторонних клиентов |
| Отдавать JSON с тех же обработчиков по `Accept` | Один набор обработчиков | Смешивает HTML и API, сложнее версионировать |
| Отдельный API-пакет с тем же слоем сервисов | Чистый контракт | Дублирует валидацию и маршруты |

## Риски и открытые вопросы

Без решения по аутентификации ([ADR-0005](../../architecture/adr/0005-demo-auth-without-state.md)) POST-операции откроют запись данных анонимам; нужна политика CORS и ограничения частоты; контракт придётся синхронизировать с доменной моделью и роадмапами.

## План внедрения

Не определён. Если RFC будет возобновлён: свести контракт с моделью, добавить тесты на соответствие схеме, выбрать способ защиты записи.

## Критерий принятия

Появление требования заказчика на стороннего клиента и решение по аутентификации. До этого RFC остаётся отложенным.
