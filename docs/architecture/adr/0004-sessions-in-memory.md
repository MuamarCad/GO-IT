# ADR-0004: Серверные сессии в памяти для кейсов и форм

**Статус:** Принят
**Владелец:** Tech Lead
**Обновлено:** 2026-11-13
**Дата решения:** 2026-11-05

## Контекст

Кейсам нужно помнить ход прохождения, а формам — CSRF-токен. Учётных записей нет, база сессий не нужна, команда хочет запускаться без внешних сервисов.

## Решение

Сессия хранится в памяти процесса (`session.Manager`), в cookie лежит подписанный (HMAC-SHA256) идентификатор. Срок жизни 24 часа; записи появляются только после сохранения; данные при чтении и записи копируются глубоко, чтобы запросы одной сессии не делили карты.

## Рассмотренные альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---------|-------|--------|------------------|
| Состояние в cookie (JWT или подписанные данные) | Без серверной памяти | Лимит размера, ход кейса виден клиенту | Ход кейса не должен храниться на клиенте |
| Сессии в PostgreSQL или Redis | Переживают перезапуск | Новая зависимость и миграции | Избыточно для демо |

## Последствия

Плюсы: нет внешних зависимостей, просто тестировать. Минусы: после перезапуска сервера открытые формы получают 403 (в журнале записывается причина), сессии не работают на нескольких экземплярах, память растёт с числом посетителей до истечения срока (лимита числа сессий нет).
